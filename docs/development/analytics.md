# Аналитика: устройство и эксплуатация

## Источники и права

`/admin/analytics` — одна страница с подразделами, доступная администратору. API независимо проверяет роль и живую сессию. Модератор/ментор не получает отчёты. Веб-аналитика: браузер → собственный Umami → серверный адаптер Next → админка. Аналитика заявок: PostgreSQL → Go → Next BFF → админка. Данные источников загружаются независимо: сбой Umami не прячет заявки.

- `GET /api/admin/analytics/traffic?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`.
- `GET /api/admin/analytics/requests?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` → Go `/api/v1/admin/analytics/requests`.
- Обе даты включены, диапазон 1–366 дней, Москва (UTC+3). Браузер предлагает 7/30/90 дней, по умолчанию 30.
- Пустая подключённая система, неподключённая система и ошибка — разные состояния. Отсутствие данных не подменяется нулевыми результатами или демонстрационными массивами.
- Кэш отчёта Umami до 30 секунд в памяти одного процесса. Проверка сессии выполняется до каждого чтения, включая попадание в кэш.

## Umami

Контракт проверен с self-hosted **3.4.1**, а не с произвольным master. Stats — плоские числа и `comparison`; временные ряды — `pageviews` и `sessions`, строки `{x,y}`. Метрики страниц используют **type=path**, не `url`.

Настройки браузера, доступные публично и обязательные при сборке:

- `NEXT_PUBLIC_ANALYTICS_PROVIDER=umami`;
- `NEXT_PUBLIC_UMAMI_URL` — HTTPS-адрес Umami (HTTP допускается для локальной разработки);
- `NEXT_PUBLIC_UMAMI_WEBSITE_ID` — публичный ID сайта.

Настройки только сервера:

- `UMAMI_API_URL` — HTTPS-адрес отчётов, HTTP допускается только для loopback;
- `UMAMI_API_TOKEN` — bearer-токен отдельного пользователя с правами чтения;
- `UMAMI_WEBSITE_ID` — тот же сайт.

Пароль, токен отчётов и приватные настройки не являются `NEXT_PUBLIC_*` и не передаются аргументами сборки. В контейнере frontend нужны серверные настройки; остальные контейнеры не должны получать токен Umami. При смене пароля/ротации токена обновить приватное окружение и перезапустить frontend. При изменении публичных настроек **пересобрать** frontend. CSP разрешает только origin настроенного HTTPS Umami.

Таблицы страниц, источников и устройств показывают уникальных посетителей группы, не число просмотров. Их нельзя складывать для получения общего числа людей. Страницы ограничены первыми 500 строками, источники/события/кампании — 100; это не полный экспорт событий. Общие посетители за период берутся из stats, не суммируются по дням. Umami referrer-метрика перечисляет внешние источники; прямые заходы не выводятся отдельной строкой этой метрики.

### Сбор

Скрипт загружается после согласия на аналитику. Автоматические просмотры, захват кликов и performance отключены; приложение отправляет явные безопасные payload. В режиме Umami GTM/PostHog не инициализируются. При каждом событии повторно проверяются согласие и DNT. Приватные кабинеты, авторизация, отзывы и dev-страницы не собираются; query/hash и произвольные заголовки/рефереры не отправляются. Исключение — ограниченные UTM-метки `utm_source`, `utm_medium`, `utm_campaign`: латинская буква в начале, затем буквы/цифры/`_`/`-`, до 64 знаков; email, свободные фразы и token-подобные значения не принимаются. Не использовать персональные данные в названиях кампаний.

События — явный allowlist. Не передавать ФИО, email, телефон, текст поиска, заявки или идентификаторы заявок. Исследования отправляют событие открытия/скачивания PDF. В существующих вакансиях пока нет действующего отклика, а в исследованиях — отдельного поля/контрола оригинального источника; соответствующие события разрешены на будущее, но интерфейс и результат не выдумываются. Session replay/heatmaps и идентификация людей не включены.

Важное ограничение: это прикладная минимизация, не юридическое заключение. IP/технические сведения видит сервер Umami; до production согласовать размещение, логи, хранение/удаление, политику и основания обработки. Блокировщики и отказ от согласия означают, что веб-трафик не является полным учётом людей.

## Заявки и история

Миграция 000018 добавляет `request_status_events`, границу истории и триггер. На INSERT — начальное событие; на фактическое изменение статуса — переход. Повторное присвоение того же статуса не создаёт событие. Запись атомарна с изменением заявки и охватывает API/worker/админку. Приложение и worker могут читать историю, но не менять её напрямую. Удаление заявки каскадно удаляет её события.

- **Новые заявки:** дата создания в выбранном периоде; сравнение с таким же предыдущим периодом.
- **Текущие статусы:** текущее состояние заявок, созданных в периоде, не состояние на последнюю дату периода.
- **Дневные завершения/отказы:** фактические записанные переходы в выбранный день, даже если заявка создана раньше. Возврат администратором и повторное завершение — ещё один переход, не ещё одна уникальная заявка.
- **Прохождение этапов:** все этапы, включая создания, считаются по одной группе заявок с полной историей. Отображается отдельная воронка с долей от созданных в этой группе; без полной истории — сообщение о накоплении данных вместо графика и нулей. Одна заявка учитывается на каждом достигнутом этапе к моменту отчёта. Это не жёсткая линейная воронка: администратор может пропустить этап. Старые заявки остаются в текущих статусах, но не получают придуманных переходов. Покрытие полной историей показано явно.
- **Время в статусе:** завершённые интервалы между событиями, медиана/p90/число наблюдений. Повторные посещения этапа — отдельные интервалы. Полный цикл — от создания до первого записанного завершения. Только заявки, созданные после начала истории; текущие незаконченные интервалы не включены.
- **Требуют внимания:** все `pending` с возрастом **не менее 72 часов с создания**, независимо от дат отчёта. Отображаются агрегаты по менторам и дата самой ранней заявки, со ссылкой на защищённый список заявок ментора. Не отправляем bearer-ID заявок в аналитический JSON.
- Время отражает отметки участников, не доказанное время общения. Отсутствие отметки не доказывает бездействие.

## Локальный запуск

Umami вынесен в отдельный Compose-проект: см. `infra/local/umami/README.md`. Приватные файлы `.env`, `credentials.json`, `integration.json`, `web.env` исключены из Git и имеют права 0600. `web.env` сопоставляет поля integration.json с перечисленными переменными; `infra/local/start.sh` подхватывает его при запуске native Next.

Локальная платформа: `http://127.0.0.1:3100/dev`, затем вход администратором и «Аналитика». Umami: `http://127.0.0.1:18185`. Не смешивать localhost и 127.0.0.1 при использовании сессии. Контур разработки содержит тестовые записи; его посещения — проверки разработки, не показатели клиентского production. Umami исключает известные headless/bot user-agent: HTTP 200 ingestion не всегда означает сохранённый просмотр; проверять отчёты/БД.

## Проверки и production-gates

Тесты бизнес-SQL запускаются только на отдельной `openmentor_analytics_test` на loopback 5546; guard проверяет имя БД и порт **до** dbtest.Pool. Нельзя использовать editing-БД 5544 или старую 5433 для разрушительных тестов. Проверить триггеры под om_api/om_worker, откат, каскадное удаление, отсутствие дубликатов и отсутствие ложной истории.

Перед клиентским запуском: отдельный Umami/БД с резервным копированием, read-only reporting-учётка, новые секреты/домен/HTTPS, публичные настройки в сборке, проверка CSP, реальная отправка события браузером и readback, проверка прав и удаления данных. Миграцию откатывать только вручную: down удаляет накопленную историю без возможности её восстановления из текущих статусов. Метрики HTTP новых BFF-маршрутов включены через withObservability; алерты исходного OpenMentor не применяются к клиенту автоматически.
